## 1. 何をするものか

図鑑埋め支援の「カメラで登録」は、ゲームの図鑑の一覧を写した **写真・スクショ・動画** から、ポケモンごとの登録（捕まえた／見ただけ／見ていない）を読み取り、結果の画面で確認してから `S.dx.reg[作品][全国番号]` に反映する。

読み取りは2段構え：
1. **スマホ内**（端末の中で読む。無料・速い）
2. スマホ内で読めなかった画像だけ **Gemini**（運営者がキーを設定しているとき）

スマホ内で読める作品は `DX_READERS`（`poke-tools/index.html`）に登録されたもの。

| 読み方 | 作品 | 関数 |
|---|---|---|
| 第7世代専用（赤い帯をさがす） | SM・USUM | `dxr…`（`DX_READERS.gen7`） |
| 型紙（作品ごとの「どこに何があるか」の表） | 赤緑青ピカ（`rgby`）・RS/E（`rse`）・FRLG・DP/Pt（`dp`・`pt`）・HGSS・ORAS・剣盾・BDSP・Z-A・SV | `dxt…`（`DX_READERS.tpl`） |

それ以外の作品（金銀・BW/BW2・XY・Let's Go・LA・HOME）は、今は Gemini でしか読めない。

## 2. 型紙のしくみ（`dxt.js`）

ソースは `poke-tools/dev/dxt/dxt.js`。アプリには `tools/inject.py` で `index.html` の `/*DXT-BEGIN*/`〜`/*DXT-END*/` に、型紙 `DXT_PROF`（型紙の名前→型紙）・`DXT_GAME`（作品 id→型紙の名前）といっしょに埋め込む。**`index.html` の中を直接直さず、`dxt.js` を直して inject すること。**

1枚の読み方（`dxtRead` → アプリからは `dxtRows`）：
1. **ゲーム画面さがし**（`dxtBox`・`dxtScreens`・`dxtMap`）：黒い余白で区切られた四角から、型紙の画面の形（`W`×`H`）に合うものを候補にする。全体の形が合えば全体。DS・3DS の2画面（並べ方・大きさがちがってもよい）にも対応。面積 8% 未満の候補は捨てる。
2. **一覧の画面か**（`P.chk`）、**どの図鑑か**（`P.dex`：`cls`＝特徴の見本、`fref`/`fmin`＝見出しの形、`refs`＝図鑑ごとの見出しの形と最大の番号）。
3. **行の位置**：一覧が途中で止まる作品は `rows.scroll`（縦）・`cols.scroll`（横）で、位置を少しずつずらして数字がいちばんよく読める位置を使う。マス目は `P.cols`（k＝行×列の数＋列）。
4. **数字**（`dxtGlyphs`）：大津の方法で文字と地を分ける。`ink`：`auto`（少ないほうの色）・`best`（L/R/G/B/あざやかさで一番分かれるもの）・`light`・`dark`。`colMin`（点だけの列は外す）、`edge`（上から下まで続く形・列は境目の線として外す）、`split`（くっついた数字を一番細い所で分ける）。1字ずつ 12×16 にそろえ、見本 `tm`（と2組目 `tm2`）と相関で比べる（`dxtCorr`）。
5. **番号を決める**：
   - ふつう（`dxtDecode`）：「上から（マス目は左上から）1ずつ増える」ことを使い、画面全体でいちばん合う先頭の番号を選ぶ。`digits:0` はけた数が変わる番号。`dxtSure`：4行以上なら合わない行は1行まで。さらに行ごとに2けた以上合う行だけ使う。
   - 番号が飛ぶ一覧（`num.seq:false`、SV）（`dxtIndep`）：本ごとに番号を読み（どの字も相関 0.55 以上・2番目と 0.06 以上の差）、左から右へ増える「いちばん長い並び」だけ使う。`dxtSureI`：3冊以上、かつ読めた本の 3/4 以上。一覧の端で切れた列（`cols.xmin`・`xmax` の外）は読まない。図鑑ごとの最大の番号は `dex.refs[].max`。
6. **状態**（`dxtFeat`→`dxtNear`）：`feat` の四角ごとに明るさ・ばらつき・白・黒・あざやかさ・赤みの6つ（＋形の見本 `fref` との似かた）。状態の見本 `cls`（複数の中心）にいちばん近いもの。遠すぎれば `unknown`。名前の `_c` などの後ろは外す（カーソルの行用の見本）。
7. 読めない画面は `{fail:'nolist'}`（一覧がない）または `{fail:'num'}`（番号を確かめられない）→ Gemini に回る。

## 3. アプリ側の流れ（`poke-tools/index.html`）

- 図鑑の選び方：`dxDexKey`。**選んでいなければ全国図鑑**（全国図鑑のない作品はその作品の図鑑）。図鑑の番号表は `DEXN[図鑑番号]=[最初の番号, 全国番号の並び]`、作品と図鑑は `DX_GAMES`。
- 行→ポケモン：`dxSetRows` が行に図鑑（`dex`）を付け、`dxSpOf` がその図鑑の番号表で全国番号にする（`'nat'` はそのまま）。録画の途中で図鑑を切りかえても取りちがえない。
- 同時読み：Web Worker 2〜3個（`dxPool`）。Worker の中身は `DX_READERS` の `fns`・`vals` の `toString()` から作る。**`dxt.js` に関数を足したら `DX_READERS.tpl.fns`（定数なら `vals`）にも足すこと**（足し忘れると Worker の中で読めず、`console.warn('dx worker',…)` が出る）。
- 動画（`dxVideoFrames`）：再生しながら 0.1 秒ごと（`DX_VID_STEP`）に横96の小さな画像で前のコマとの違いを測り、止まった区間ごとに1枚取る。再生中に取ったコマはその場で Worker に渡して読む（`dxReadBm`）。再生の速さは 1〜3倍を自動。型紙の作品（`dense:true`）は 0.2 秒ごと・止まっている基準を低く・見た目が似たページも省かない。
- **2026-10-26 に足したもの**：
  - 型紙の作品（SV 以外）は、**動いている途中のコマも取って読む**（`capture(...,mv)` → `File.dxMov`）。ORAS でボタンを押しっぱなしにすると、ページの境目の行が止まった画面ではいつも半分しか写らず、動いている途中にしかまるごと写らないため。
  - `dxReadLocal`：止まった画面の結果をまとめたあと、止まった画面で読めなかった番号だけを、動いている途中のコマの **多数決** で埋める（同じ数なら `unknown`）。止まった画面で読めた番号は変えない。
  - `dxGapFill`：それでも、続けて取った2枚のあいだで番号が飛んでいたら、その2枚のあいだの「動いた時刻」の前後のコマ（1/30 秒きざみ、1か所12コマまで、全部で900コマまで）を、位置を移して取り出して読み直す（これも多数決）。動いた時刻は `File.dxMot`（動画のファイルに付けた、時刻と違いの大きさ）。
  - SV（`dxNoSeq()`）は動いている途中のコマも番号の抜けの読み直しも使わない。同じ本を何枚もの画面で読むので、**印は多数決**。
  - 「読めなかったページ」（`dxScan.gaps`、要素は `[から, まで, 図鑑の名前]`）は、**録画した画面の図鑑ごとの番号の抜け**（`dxReadNums`：図鑑ごとに読めた番号）で出す。出すのは、選んでいる図鑑に入るポケモンだけ。SV は出さない。図鑑の情報がない読み方（SM・USUM・ORAS の型紙など）は、前と同じく選んでいる図鑑の並びで数える。
- **2026.10.26b**：Gemini と連携しているときの読み方（`dxReadGm`）でも、上の埋める処理（`dxLocalFill`）を AI に送る前に使う。スマホ内で読めたポケモンは AI の答えで変えない。`dxGapFill` は2枚の番号の範囲の中の抜けも読み直す。テストは `GM=1 tools/apptest.py …` で Gemini 連携ありの流れ（通信は止める）。
- **2026.10.26c（速さ）**：`dxtInk` の `best` を度数で数える形に（ORAS 1枚 1.6秒→0.24秒）。`dxGapFill` は位置を移すのを減らし、2倍速で再生しながら取る・同時に読む・時間の上限（動画の長さの半分、最大60秒）。「くわしく」に取り出し・読み直しの時間を出す。
- **2026.10.26e**：動いている途中のコマだけで決まる「捕まえた」は2枚以上そろったときだけ（1枚なら読み直しでもう1枚を読みにいき、それでも1枚なら「不明」）。
- **2026.10.26g（図鑑のタブ）**：図鑑が複数ある作品は、図鑑の画面にタブ（`#dxTabs`・`dxViews`・`dxEntriesOf`）。読み取りは作品のすべての図鑑に振り分け（`dxAllSp`）、結果の画面にも図鑑ごとのタブ（`dxScan.view`）。Gemini には図鑑名（`dex`）も答えてもらう。
- **2026.10.27a**：型紙に RS/E・DP/Pt・HGSS を足した。`dxt.js` に、型紙で使うときだけ効く3つ（`num.one`・`num.pre`・`rows.at`）を足した。今までの型紙には書いていないので、読み方は変わらない。
- 結果の画面：`renderDxScan`（`dxs-…`）。LEGENDS アルセウスだけ「自分で捕まえた」（1）と「登録だけ」（2）を分ける（`dxOwn()`）。

## 5. 進行中・やり残し（優先の順）

2. **段階3の残り**：BW/BW2 → XY の型紙を作る（手順は `README.md`）。RS/E・DP・HGSS は 2026-10-27 に済み。BW/BW2・XY の録画はまだもらっていない（前の担当の作業場所にしかない）。
   - Pt の録画、RS/E・HGSS の「地方の図鑑」（ホウエン・ジョウト）の画面の録画があれば、確かめる。RS/E・HGSS は画面から図鑑を見分けないので、地方の図鑑の録画は、その図鑑を選んでから読んでもらう必要がある（選んでいなければ全国図鑑として数える）。
3. **後回しにした作品**（運営者の指示「まだわからないことがある世代は一旦放置」）：金銀クリスタル、Let's Go（マス目と詳しい画面の2種類の録画がある）、LEGENDS アルセウスの型紙読み。2026-10-27 に金銀（しんがたずかん、名前だけの一覧）と Let's Go 2本の録画をもらった（下の6）。

   - Let's Go：詳しい画面には「図鑑No.」と「捕まえた記録」がある。もらった録画は全部捕まえた状態（151/151）で、「見ただけ」の画面の見本がない。
4. 気になっている小さなこと：
   - ORAS で捕まえた・見つけたが画面より1匹ずつ多い（どの番号かは未調査。動いている途中のコマの多数決で、1つだけまちがえている可能性）。

## 6. 作業場所とテストのしかた

2026-10-27 の録画 8本（赤緑・金銀・Let's Go 2本・HGSS・DP か Pt・エメラルド・RS）は、Grok Bot の作業場所（`/workspace/dexvid/`、止まった画面は `/workspace/dexgen/st/`）にある。リポジトリには入れていない。

前の担当の作業場所（`/home/claude/gen`）は**リポジトリに入っていない**。中身：
- `v/`：運営者の録画（g1・g2・rs・e・frlg・dp・hgss・bw・b2w2・xy・oras・g7a/g7b（Let's Go）・swsh・bdsp・la・sv・svk・svb・za、sw_rec.mov（SV の Switch 本体の録画））。**新しい担当は、運営者にもう一度もらう必要がある。**
- `wv/`：テスト用に webm にしたもの（Playwright の Chromium は H.264 を再生できないため。`ffmpeg -i 元 -an -c:v libvpx-vp9 -deadline realtime -cpu-used 8 -b:v 4M -vf scale=1280:720 wv/名前.webm`）。
- `st/`：`tools/stills.py` で取り出した止まった画面。`truth/`：止まった画面を読んで作った「正解表」（図鑑ごと）。**正解表は自分の読み取りから作ったものなので、抜けがあり、画面の数（捕まえた・見つけた）とくらべるのが本当の確かめ方。**
- 道具（`tools/`）・`dxt.js`・`harness.html`・`prof/` は、このフォルダーに写してある（同じもの）。

テスト：
